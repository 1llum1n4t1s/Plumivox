# Plumivoxをセットアップする

同梱の[導入手順](../../docs/setup.md)を読み、利用者の現在位置から進める。資材はこのプラグイン内の`setup/Setup-Plumivox.ps1`と`setup/vps/`を使う。別リポジトリ、開発クローン、特定の利用者の保存先へ依存しない。

読取り・検索だけならAPIキーとXユーザー名の設定で足りる。投稿には認証付きの公開プロキシとセッションが必要。自宅回線を使う場合は、利用者のVPSの公開プロキシ → SSH逆トンネル → 起動中のWindows PCという経路を構築する。

- PCの専用鍵準備 → 公開鍵と資材の転送 → VPSの`--check`とインストール → PCの設定ウィザード → ローカル`-Check`とMCPの`start_proxy`の順に進める。必要な利用者操作は場所・操作・返してほしい結果を簡潔に示す。
- VPSへの変更は利用者が構築を依頼した対象と範囲に限る。新規契約・購入は行わない。既存サービスの削除、ファイアウォールの一括変更、管理者SSH設定の緩和で衝突を回避しない。
- APIキー・パスワード・TOTP秘密鍵はウィザードの秘密入力で受け取る。会話・MCP引数・コマンド引数・ログに秘密値を求めない。VPSへ送る鍵は`.pub`だけ。秘密鍵はPCへ残す。
- SSH指紋は利用者がVPS事業者のコンソールなどの信頼できる経路で確認する。`ssh-keyscan`の結果だけを信頼せず、ホスト鍵検証を無効にしない。
- プラグインはGitHubの最新`main`から取得する。`codex plugin add ... --json`の`installedPath`を使い、キャッシュのバージョン名を推測しない。`config.toml`へ登録行を追加しない。
- Windowsの実行例は`pwsh -NoProfile -ExecutionPolicy Bypass -File ...`を使い、取得元を確認した同梱スクリプトの子プロセスに限定する。永続ポリシーや組織の制限は変更しない。
- `-Check`はローカル設定だけ、`start_proxy`はPC出口とSSH中継の確認。公開口への到達・実ログイン・投稿成功を確認済みと扱わない。セットアップだけの依頼ではログインや投稿を実行せず、追加の依頼があればその範囲で行う。

既存設定の保存先・アカウント追加は[設定](../../docs/configuration.md)、中継の起動・停止と共有動作は[管理プロキシ](../../docs/managed-proxy.md)で確認する。初回構築に必要な説明を毎回の投稿前チェックへ増やさない。
