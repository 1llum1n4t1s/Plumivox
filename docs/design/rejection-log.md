# 拒否文面の記録

[秘密・通信・プロキシの境界](security.md)の唯一の例外である、提供元の拒否文面をローカルに記録する仕組みの詳細。

`src/rejection_log.rs`が担う。`plumivox --rejection-log on [--days N]`（1〜30日、既定7日）で有効化し、期限が切れると自動で記録を止める。`off`・`status`・`show`・`clear`も同じCLIにある。

- **対象**：`post_tweet`の画像アップロードと投稿作成の`API_REJECTED`、および投稿IDが返らない`POST_UNCERTAIN`。読取り・ログインは記録しない。2xxで拒否を示した本文に加え、記録が有効なときだけ、投稿作成・画像アップロードの2xx以外の応答本文も64KiBまで読み、同じ規則で伏字して記録する（結果と分類が決まった後に、同じ時間制限の残りと1秒の小さい方まで読む。この読み込みは画像の再試行の判断より前に行うので、上限が無いと本文がゆっくり届くとき画像ごとの期限を使い切って記録の有無で再試行の挙動が変わってしまう。読めなくても分類は変えず、文面なしの1件として記録する）。2xx以外の分類はHTTP状態だけから付け、本文からは付けない。記録が無効なときは本文を読まない。読む欄は`message`・`msg`・`error`・`error.message`・`detail`・`errors[].message`に限る。本文の数字のコード（最上位の`code`・`errors[].code`）は`provider_codes`として残す（応答には表にあるコードだけを`xErrorCode`で出す）。request IDは記録しない。MCPの応答に`rejectionTextRecorded: true`を足すのは、最終エラーと段階・要求の通し番号が一致する1件を記録できたときだけで、別の段階の記録や、その後の記録なしの失敗には付けない。
- **伏字**：制御文字と空白を整え、既知の秘密（APIキー・Cookie・プロキシ・ユーザー名・プロファイルの文字列など。送信前に設定から集め、すべて最初の規則で処理する）と本文を完全一致で置換し、本文と共通する10文字以上の断片、URL・メール・`key=value`の秘密・IP/ホスト・`@ユーザー名`・トークン状の文字列・5桁以上の数字を種類別の印へ置き換える。1欄500文字で切り、伏字後に既知の値や本文の断片が残れば、その欄の文面を捨てる。記録する`account`は設定名だけで、Xユーザー名と大文字小文字を無視して一致するか、既知の値を含むときは`<user>`に置き換える。
- **保存先と保護**：状態ルート（`PLUMIVOX_STATE_DIR`に従う）の`diagnostics\provider-rejections.jsonl`（JSON Lines）。有効化の状態は同フォルダーの`rejection-log.json`。フォルダー・ファイルは本人限定とし、リンクは拒否し、検査に失敗したら書かない・消さない。書込みは排他を取り、`session.rs`の保存作法を共有する。排他が取れない1件は捨て、投稿や再試行を失敗させない。
- **上限**：1件14日、200件、256KiB。超えたら古い順に消す。
- **閲覧**：CLIの`show`が標準出力へ出すだけで、MCPツールは作らず、MCPサーバーの標準出力・標準エラーにも出さない。`clear`で記録を消す。
