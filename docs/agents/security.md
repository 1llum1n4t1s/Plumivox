# 資格情報・保存先・投稿の安全条件

標準出力、資格情報、設定・セッションの保存先、Cookie、認証更新、投稿の再試行に関する制約。

- 標準出力はMCP通信専用。資格情報、復号Cookie、設定ファイルの内容、提供元の生エラーを応答や診断へ出さない。資格情報は設定ストア経由で取得し、MCP引数に追加しない。生エラーは既定では保存しない。例外は、利用者がCLI（`--rejection-log`）で期限付きに有効にしたときだけ、伏字処理した拒否文面を本人限定のローカルファイルへ記録することで、MCPの応答とMCPサーバー（stdio）の標準出力・標準エラーへは出さず、閲覧はCLIの`show`が標準出力へ出すだけにする（[設計](../design/security.md#拒否文面の記録)）。伏字の規則・保存先・閲覧経路を変えるときは、reviewerの審査とE2Eを必須にする。対象は、2xxの拒否本文に加え、記録が有効なときだけ読む投稿作成・画像アップロードの2xx以外の本文（読む欄に`detail`を含む）である。
- 設定ファイルの選択順と起動時の固定を維持し、選択後の読込み失敗で別ファイルへ切り替えない。各OSのセットアップとMCPの既定保存先を一致させる。セットアップでは既存鍵・同名アカウント・共有中継設定の上書きを拒否し、保存先・権限・排他・保存直前の設定再確認を維持する。権限設定は本人所有を確認してから行い、所有者を変更せず、適用後にも検証する。WindowsのDPAPI互換とmacOSのKeychain／AES-GCM、本人限定のファイル権限を維持し、Keychain利用不能時に平文へ切り替えない。
- 読取りと投稿の準備条件、Cookieの優先順位・照合、認証更新の排他と設定再確認を維持する。公開投稿の読取り4ツールはセッションの検査・読込み・復号を行わず、変更時はAPI系E2Eの計測で確認する。状態一覧とCookie再利用判定の境界は [設計のデータフロー](../../DESIGN.md#データフロー) に従う。Mutex所有喪失後の保存を防ぎ、置換指示後の結果不明を未変更と断定しない。保存・通信・キャンセル失敗の検証も含める。
- 投稿作成・ログインを自動再試行しない。画像アップロードだけの再試行条件・時間枠と投稿エラーの段階情報は [設計の不変条件](../../DESIGN.md#不変条件と採用した設計判断) を維持し、要求回数・取消・成否不明をAPI系E2Eで検証する。投稿IDが確認できない結果を成功にしない。認証更新から投稿を再送しない。
- 本文の重複を理由には投稿を止めない（同じ文面の明示呼出しも、冷却中でなければ各回送信する）。止めるのは時刻に基づく冷却ガード（`src/post_guard.rs`、Xのユーザー名ごとの`<状態ルート>/post-guard/<hash>.json`とファイルロック）だけで、冷却中は何も送らず課金も起こさず`POST_COOLDOWN`、保存先が使えなければ`POST_GUARD_UNAVAILABLE`で止める（fail-closed）。冷却はMCPからは解除できず（ツールを作らない）、利用者本人がCLI（`--post-guard status` / `clear [--account NAME | --user NAME]`。`clear`は端末での確認入力が必須）で確認・解除する。順序（`get_account`→`prepare_post`→`acquire`→`ensure_proxy`→`send_recorded`→`finish`）、規則の表（strikeを数えるのはXの拒否と分かるときだけで、`xRejected`の無いHTTP 429は固定15分。投稿作成段階の`proxy`拒否は`min_interval`）、状態に入れるもの（固定のコード・分類・時刻だけ。設定名がユーザー名を含むだけでも`<user>`）、新しいschemaの状態は上書きせず`guard_state_reset`の拒否だけ返す扱いは [設計](../design/security.md#投稿の冷却ガード) に従い、待って後から送る実装にしない（自動再送と同じになるため）。シェルを使えるエージェントはCLIや状態ファイルの削除で解除できてしまうため強い防御ではないが、それを理由に解除を試みない。`POST_COOLDOWN`の`nextStep`は、`min_interval`・`post_in_progress`のときだけ「`retryAfter`の後に1回呼んでよい」、それ以外は「本人に伝えて待つ」と分ける。AIが読む文言（`nextStep`・ツール説明）にCLIのコマンド名は書かない。冷却の規則・状態・解除の経路を変えるときはE2E（`guard_cases`）を更新し、保存処理の挙動を変えるのでreviewerの審査を通す。
- 2xx以外の応答本文は、拒否記録が有効なときだけ（投稿作成・画像アップロード、64KiBまで）読み、伏字して記録する。無効なときは読まない。分類はHTTP状態だけから付け、本文の整数をXのコードとして扱わない。数字のコードの対応表にない生のコードは応答に出さない（[設計](../design/api-reference.md)）。
