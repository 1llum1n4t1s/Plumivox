# 検証方針

実装前に想定する失敗を以下に定義する。ユニットテストは追加せず、MCPクライアントから独立したサーバープロセスを呼び出すE2Eで検証する。

セットアップは独立したPowerShell・Bashプロセスから同梱CLIを呼び出して検証する。想定する失敗は次のとおり。

| セットアップの失敗条件 | 期待する結果 |
| --- | --- |
| 別のWindows利用者が初回起動する | その利用者の保存先を選び、特定利用者の絶対パスを参照しない |
| 選択済み設定が不正・消失 | 別ファイルへ切り替えず設定エラー |
| 既存鍵・既存プロファイル・中継設定がある | 上書きを拒否し、既存情報を保持 |
| 保存先がリンク・リポジトリ・Codex内、ACLが不適切 | 保存前に拒否し、秘密値を公開しない |
| ホスト指紋・ポート・2FA秘密鍵・秘密鍵が不正 | ローカルで拒否し、API・SSH通信を行わない |
| 書込み準備中に設定が変更された | 検出した変更を上書きしない |
| VPS CLIが不正引数・パスワード引数を受け取る | 変更コマンドを呼び出さず拒否 |
| root権限・対応OS・UFW・SSHの準備が不足 | 原因を示して停止し、既存設定を変更しない |
| VPSのSquid・専用利用者・ポートが競合する | 既存サービスを停止・上書きしない |

`tests/setup-e2e.mjs`は専用鍵の生成とACL、設定の保存・保持・拒否、保存先の選択、ローカル確認を検証する。`tests/setup-vps-e2e.mjs`はBash構文、実CLIのヘルプ・不正入力・権限拒否と変更コマンド未呼出しを検証する。WindowsのGit Bash検証では、Linuxでのパッケージ導入・Squid起動・SSH認証の成功は未検証である。実VPSへの接続・ログイン・投稿はこのE2Eでは行わない。

| 失敗条件 | 期待する結果 |
| --- | --- |
| 複数の投稿先がありaccountが省略された | アカウント指定を要求し、通信しない |
| 64文字を超える設定済みアカウント名 | 一覧に表示した名前をそのまま指定して読取りできる |
| APIキーがない、Cookieがない、保存Cookieの照合が不一致 | 秘密を表示せず設定エラー。読み込みにはCookieを要求しない |
| 空の投稿、280の加重文字数を超える投稿 | アップロード・投稿前に拒否 |
| URL、日本語、複合絵文字が含まれる投稿 | twitter-textの加重文字数とUnicode 17の複合絵文字の重み2で判定。280は送信し282は通信前に拒否 |
| 画像の形式不正、サイズ超過、相対パス、5枚以上 | 送信前に拒否 |
| 4画像のアップロード、途中の画像で失敗 | 事前検証した画像の順序・内容を維持し、途中失敗では投稿を送信しない |
| APIの401/429/5xx、非JSON、HTTP 200内のerror | 秘密や提供元の生エラーを返さず失敗として返す |
| 10MiBを超えるAPI応答、UTF-8文字途中の通信分割 | 上限超過で受信を打ち切る。上限内の分割文字は正しく復号する。投稿の超過応答は成否未確定として再送しない |
| 投稿成功に見えるが投稿IDがない、通信の成否が不明 | 成功扱いせず、自動再送しない |
| 同じ投稿を明示的に二度呼び出す | 各呼び出しで一回ずつ送信する。ローカル履歴で停止しない |
| フォロー先が空、保護アカウントを含む、一覧が複数ページ | 公開投稿の取得範囲・未取得範囲を明示 |
| フォロー先検索が複数バッチで重複・順不同 | 投稿IDで重複を除き、日時の降順にする |
| 日時欠落・不正日時・1970年以前・同時刻の投稿が混在 | 従来の日時キーと数値IDの比較規則を維持する |
| フィードの続きを別アカウント、改変した署名付きcursor、旧署名なしcursorで要求する | 通信前に拒否。正しい署名付きcursorなら初回の検索対象で継続 |
| フォロー先一覧に保護状態のフィールドがない | 対象アカウントの未知数をcoverageへ残し、保護アカウント除外を保証しない |
| 取得対象の上限より後に、選択済みアカウントの既知公開の重複がある | 初出順・取得上限を維持し、そのアカウントを保護状態不明の件数へ含めない |
| 提供元cursor、複数バッチの合計、署名付きwrapperが長さ上限を超える | 取得済み投稿と提供元のhasNextPageを保持し、cursorを切り詰めず、継続不能の理由とnullのnextCursorを返す |
| X全体またはフォロー先をキーワード・期間で検索 | キーワードを語句として扱い、期間をAPIの検索条件へ渡す。フォロー先条件を解除する演算子として扱わない |
| 空キーワード、不正日時、終了日時が開始日時以下の期間 | HTTPを呼ばず安全に拒否。開始は含み、終了は含まない |
| 検索の続きを別アカウント・対象・キーワード・期間・フォロー上限で要求、またはcursorを改変 | HTTPを呼ばず拒否。既存フィード用cursorと検索用cursorも混同しない |
| 全体検索へフォロー一覧のcursorやフォロー上限を指定 | 無関係な引数を黙って無視せず、HTTPを呼ばず拒否 |
| MCP標準出力に診断ログが混ざる | 標準出力はMCP通信だけにする |
| 利用者が画像アップロード中にMCP要求を中止した | API要求を中断し、その後の投稿要求を開始しない |
| ログインに必要なメール・パスワード・プロキシが不足 | APIを呼ばず、必要な設定項目だけを安全に返す |
| 複数アカウントがある状態で保存Cookieを再利用 | 設定を読み直し、選択済みアカウントだけのセッションを確認する。他アカウントは復号しない |
| ログイン成功応答にCookieがない | 成功扱いせず、保存済みセッションを維持 |
| ログインの401・拒否・非JSON・タイムアウト | 秘密を返さず、投稿やログインを自動再送しない |
| Cookieを更新してMCPプロセスを再起動 | DPAPI保存セッションを読み込み、秘密値を返さず投稿準備状態を表示 |
| 復号子プロセスの出力がUTF-8文字途中で分割、または2MiB境界に達する | 分割文字を正しく復号し、上限一致までは受理、超過は保存セッションを無効として扱う |
| 新しい保存セッションが不正・別アカウント・別APIキー | 投稿を拒否し、読取りは継続。旧Cookieへ黙って戻らない |
| セッション更新に失敗・保存に失敗 | 既存の暗号化Cookieを破損せず、復元可能に保つ |
| 保存準備・暗号化中の取消やMutex所有喪失 | AUTH_CANCELLEDまたはAUTH_LOCK_LOSTとして返し、置換前なら保存セッションを変更しない |
| ログイン成功応答のCookieが保存に使えない形式 | LOGIN_FAILEDとして返し、保存済みセッションを維持 |
| 保存本体の置換を指示した後に成功応答を確認できない | AUTH_SAVE_UNCERTAINとして更新済みの可能性を伝え、未変更と断定しない |
| 同じアカウントへ同時にログインを要求 | 複数MCPプロセスでもAPI呼出前から保存完了まで排他し、競合をAUTH_BUSYとして拒否 |
| ロックを保持するMCPプロセスが終了 | ロックを解除し、次の認証更新を妨げない |
| MCPが生存したままMutex所有子プロセスだけが終了 | 待機中のログインを中断し、旧処理から保存しない。別MCPの新しいセッションを上書きしない |
| 投稿拒否後にセッションだけを更新 | 更新は行うが、失敗した投稿を自動再送しない |
| ログイン応答・標準エラー・証拠ファイル | APIキー・Cookie・パスワード・2FA秘密鍵・プロキシ資格情報を含めない |
| vava／blblの投稿手順が旧スクリプトを参照 | 全呼び出し元をPlumivoxのMCPツールへ統一し、旧専用ファイルの撤去を確認 |

E2Eでは外部サービスの代わりにlocalhostのHTTPサーバーを使い、HTTPメソッド・認証ヘッダー・本文・要求回数を記録する。検証結果は利用者の一時ディレクトリにある作業別フォルダーへ書き、終了後に必要な証拠だけLocalApplicationData配下へ保持する。実際のXへの投稿はこの検証に含めない。

## 既定アカウントの失敗条件

- 複数登録・既定なしの省略呼出しはACCOUNT_REQUIREDとして通信前に拒否する。
- 登録済みのdefault_accountがあれば、検索・読取り・投稿・認証は省略時にその設定名を使う。明示accountと既存の環境変数による選択を優先する。
- 空文字・null・文字列以外・未登録名のdefault_accountは、省略時にACCOUNT_DEFAULT_INVALIDとして通信前に拒否し、先頭や唯一の登録先へ戻らない。明示accountなら指定先を使える。
- list_accountsはdefault_accountをアカウントとして列挙せず、有効な省略先だけにisDefaultを返す。選択不能でも一覧は確認できる。
- 設定を更新・再起動しても既定を読み込み、別accountを明示した投稿を既定へ送らない。既定が変わっても既に開始した認証・中継準備の送信先を変更しない。
- セットアップは初回登録を既定として保存し、既存の有効既定は保持する。既定だけの変更でも未登録名・保存競合・読込み失敗を拒否し、アカウント資格情報や中継設定を変更しない。

## 住宅回線CONNECT出口の失敗条件

| 失敗条件 | 期待する結果 |
| --- | --- |
| CONNECT以外、443以外、許可ドメインに似た名前、IP直指定、認証付きauthority、不正なHTTPヘッダー | DNS・外向き接続前に拒否。x.com・twitter.com・twimg.comとdot区切りサブドメインだけを許可 |
| DNS候補にprivate・loopback・link-local・IPv4 mapped・予約済み等の特殊アドレスが一つでもある | 全候補を拒否し、検証済みの公開IPにだけ直接接続。接続時にDNSを引き直さない |
| ヘッダー8KiB超、CONNECT直後の先行データ64KiB超、同時接続16超 | 上限で拒否。上限内の先行データは欠落せず一度だけ上流へ渡す |
| ヘッダー・DNS・接続が15秒以内に完了しない、60秒の無通信、10分の最大寿命 | 接続とタイマーを終了し、DNS待機の継続による接続開始を防ぐ |
| クライアント中断、上流障害、出口停止、停止と起動の競合 | 全ソケットを閉じ、未完了DNSの結果から接続を開始しない。停止完了時に接続数0 |
| 別プロセスが出口ポートを使用中 | PROXY_PORT_BUSYで安全に失敗し、既存プロセスを停止しない |
| 応答・状態・標準出力に内部エラーや設定・宛先・IPが混ざる | 固定エラーとrunning・activeConnectionsだけを公開し、標準出力にログを出さない |

## 管理プロキシの別プロセスE2E

実装前に固定する失敗条件は、SSHホスト鍵不一致・公開鍵認証失敗・ローカルポート競合・起動中の取消・接続切断後の再接続・明示停止後の復活・停止中の通信残存・externalアカウントの投稿による共有中継の停止です。いずれもAPI投稿の自動再送や秘密値の出力を起こしてはいけません。CONNECTでは禁止ドメイン・private IP・公開IPとprivate IPが混ざったDNS応答を外向き接続前に拒否し、検証済み公開IPを接続関数へ渡すことも確認します。

SSH停止では、転送解除の応答まで旧リスナーの解放を遅らせ、`stop_proxy` 直後の `start_proxy` で同じポートを確保できることを確認します。転送解除に応答しないSSHも有限時間で切断し、認証中の取消・認証失敗で停止を待ち続けないことを確認します。別所有者がremoteポートを使用する場合は `PROXY_REMOTE_BIND_FAILED` の恒久失敗にし、そのリスナーを維持して自動再試行やAPI再送をしません。

同時に起動を待つ複数の要求は、それぞれ一度だけ完了させます。一つの待機を取り消しても他の待機を妨げず、停止・認証失敗では残る待機すべてに対応する結果を返します。分割したCONNECTヘッダーと同梱した先行データも、単一受信と同じ順序で転送します。

管理・共有のどちらも、秘密鍵の空ファイル・非通常ファイル・読取り不能・1MiB超をSSH/API開始前に拒否します。共通の読取り処理では読取り上限、作業Bufferの消去、ファイル解放を保ち、共有IPCは従来のドメイン文字列付きハッシュを使用します。共有側だけのホスト名小文字化・鍵パス正規化と、管理側の表記維持・null許容を変えないことも比較します。

`node tests/proxy-e2e.mjs` は別プロセスの本番MCPサーバー、ループバックの偽SSHサーバー、偽TwitterAPI.io、echoサーバーを使います。SSH逆方向転送からCONNECT出口までを通してデータを確認し、実際のXや実際のSSHホストへ通信しません。DNSと上流接続の差し替えはtestsの起動fixture内だけに置き、本番環境変数に検証用の迂回経路を設けません。

出力先は `PLUMIVOX_PROXY_E2E_OUTPUT_DIR`、未指定時はユーザーの一時ディレクトリ配下 `Codex/Plumivox/<UUID>` です。`summary.json` と `http-trace.json` に秘密を含まない結果を残します。生成した偽秘密設定とSSH鍵の清掃は呼び出し側が担当します。

## 共有プロキシdaemonの失敗条件

| 失敗条件 | 期待する結果 |
| --- | --- |
| 同じ設定で二つのMCPプロセスが同時に起動 | 一つのdaemonだけがSSHと固定ポートを所有し、両MCPからreadyを確認できる |
| 一方のMCP終了・起動待機の取消・external投稿 | 他方の中継とCONNECT通信を維持し、API投稿を再送しない |
| 一方から明示的にstop_proxy | 全利用者の中継を停止し、daemonの自動再接続で復活しない |
| 利用中のMCPが存在、または全利用者が離脱 | 利用中はidle終了せず、全離脱後に指定の待機時間でSSH・IPC・出口を閉じる |
| IPCの認証不一致、認証前コマンド、巨大frame | 認証済み状態を変更せず接続を拒否し、共有秘密・SSH鍵・設定を標準出力や証拠へ出さない |
| IPC frameを分割・一括・分割の順に受信 | 正規の認証と要求番号を照合し、受信の分割方法にかかわらず同じ応答を返す |
| 過去challenge・resultの再利用、署名後のstatus改変、同じ秘密鍵を使う別設定scopeのMAC | client/server双方のnonce・channel・requestId・全応答内容・設定contextを照合して拒否。正規の署名済み応答は受理 |

`node tests/proxy-shared-e2e.mjs` は二つの別プロセスMCP、別プロセスdaemon、ループバックの偽SSH・echo・APIで共有ライフサイクルを確認します。検証fixture内でdaemonのmanagerFactoryへ出口のDNS・接続を注入します。出力先は `PLUMIVOX_PROXY_SHARED_E2E_OUTPUT_DIR` またはユーザーの一時ディレクトリ配下 `Codex/Plumivox/<UUID>`。`summary.json` と `http-trace.json` は秘密なしの証拠として残し、偽鍵・設定の清掃は呼び出し側が担当します。

## ビルドと実行

開発時だけリポジトリをクローンします。プラグインのインストール元にはこの作業ディレクトリを登録せず、[GitHubの最新mainを参照する手順](../README.md#インストール)を使います。

```powershell
git clone https://github.com/1llum1n4t1s/Plumivox.git
cd Plumivox
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm check
pnpm test:e2e
```

`dist/plumivox.mjs` はプラグイン用の正式な実行物です。ソースを変更したときは再ビルドし、ソースとバンドルを一緒に保存します。バンドルは Node.js 22以降で動作し、依存インストールや起動時のネットワークからのコード取得を必要としません。

E2EはSDKが入力スキーマを拒否する標準MCPエラーと、アプリが返すJSONの業務エラーの両方を確認します。検証結果の `summary.json` と秘密を含まない `http-trace.json` は再現の証拠として保持できます。偽の設定・画像ファイルは検証後に清掃します。

API系の失敗1件だけを再確認するときは、`PLUMIVOX_E2E_CASE`に`summary.json`のケース名を完全一致で指定して`node tests/e2e.mjs`を実行できます。一致するケースがなければ失敗します。既定の全体検証ではこの環境変数を未指定にし、個別再実行の成功を全件成功として扱いません。
